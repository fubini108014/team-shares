01 · 為什麼總是客戶先發現

監控顯示正常，不代表使用者看到的正常

以前REACTIVE
資料或內容出錯API 正常、監控全綠
使用者先看到少資料、顯示 NaN、版面跑掉
客戶來反映信任已受影響
工程師開始查重現困難、耗時
導入後PROACTIVE
資料或內容出錯同樣的問題
巡檢員發現固定時間打開實際頁面檢查
通知 + 修復 MR附原文；前端 bug 附上修好的 MR
工程師審核看 diff 後合併，使用者還沒看到
監控看得到

伺服器狀態、API 回應碼 200、頁面打得開

監控看不到

列表少了資料、欄位顯示 NaN、資料停在昨天、HTML 殘留、版面溢出、外部連結失效

02 · AI 巡檢員

像使用者一樣，每天把網站走過一遍

對照
Browse · Playwright

畫面 × 原始資料

打開實際頁面截圖，同時攔下 API 回應。資料有幾筆畫面就該有幾筆，資料有值畫面就不該是空的。

分層
Judge · 規則 + Claude

規則守已知，AI 找未知

規則抓確定的錯（筆數、格式、程式值外露）；規則寫不出來的語意問題，交給 Claude 讀全文判讀。

證據
Report · Google Chat

看通知就能處理

指出哪一頁、哪一段，附上原文引用與截圖，收到的人不用自己重現。

Node + Playwright，不需改動受測專案 排程定時執行，正常也發一行心跳 已用在 XQ Lab：THE DESK、洞見日報
02 · 巡檢清單

巡檢員每天檢查什麼？

01規則

筆數與完整性

畫面筆數和 API 對不上、列表或卡片是空的、必要欄位缺漏。

實例：首頁顯示 2 則，應為 3 則
02規則

資料新鮮度

畫面停在舊資料，排程或同步可能中斷。

實例：首頁停在前一期，不是今天
03規則

資料轉換

原始資料格式一變，前端切錯、轉錯，卻不會報錯。

實例：分隔線打成「——」，整段沒切開
04規則

殘留與版面

NaN、undefined、HTML 標籤、亂碼外露，或內容溢出畫面。

實例：行情欄位出現 undefined
05規則

外部依賴

頁面上的外部連結、引用來源是否還在、是否被改動。

實例：引用的原文被改標題、下架
06AI

語意異常

Claude 讀全文，找規則寫不出來的問題。

實例：截斷、重複、錯置、標題與內文不符
02 · 運作流程

從排程到通知

STEP 1

排程觸發

排在資料更新之後的固定時間，錯過時開機後補跑。

STEP 2

打開頁面

Playwright 走過關鍵頁面，截圖並攔下 API 原始資料。

STEP 3

規則 + AI

規則逐項檢查，再把全文交給 Claude 找語意異常。

正常　發一行 ✅ 心跳
有狀況
  1. 🚨 規則沒過：列出 error
  2. 🤖 AI 有疑慮：附上原文引用
  3. 🔗 外部連結異動：附新舊標題
  4. 🔧 前端 bug：AI 修好、重驗、開 Draft MR
原則

AI 只提出疑慮與修復，不做決定。AI 的發現一律記為 warn 並附上原文；修復只開 Draft MR，由工程師審核後才合併。

＊單次費用取 10/5 實測：洞見日報約 $0.18、THE DESK 約 $0.15；規則檢查不花 AI 費用。

只讀不寫

巡檢只瀏覽公開頁面、不需登入；AI 只收 stdin 全文，權限設為 dontAsk，寫檔與執行指令一律拒絕。

資料範圍

目前送給 AI 的只有已公開的頁面內文，不含個資；套用到有個資的頁面時要先遮蔽。截圖與報告留在本機，30 天自動清除。

04 · 套用到你的專案

接一個新頁面，要準備什麼？

01 · 準備

定義「正確」長什麼樣子

  • 頁面網址、呼叫哪些 API
  • 應該有幾筆、哪些欄位必填
  • 多久更新一次、幾點之後算遲到
02 · 撰寫

一支 monitor-<app>.mjs

  • 打開頁面、攔下 API 回應
  • 寫這個頁面專屬的規則
  • 現有兩支各約 500 行，多半是規則
03 · 上線

接上排程與通知

  • 排程時間設在資料更新之後
  • 先開心跳，觀察一兩週誤報
  • 穩定後再加上 AI 判讀
共用

截圖、報告、Google Chat 通知、AI 判讀、心跳都在 lib.mjs，新頁面只需要寫自己的規則。

Takeaway

在客戶發現之前，
先把問題找出來。

讓 AI 巡檢員每天替團隊把網站走一遍——規則守住已知的錯，AI 找出規則寫不出來的，前端 bug 備好修復 MR，由工程師做最後決定。

05 · Q&A

常見問題

Q1

AI 會不會誤判，造成誤報？

會，所以 AI 的結果一律只記 warn，而且必須附上原文引用；只有規則沒過才算異常。看卡片就能判斷是不是真的問題。

Q2

為什麼不全部用規則就好？

規則抓得到格式（符號、編號、則數），抓不到語意：截斷、重複、段落貼錯則、引註張冠李戴。示範的五處問題，規則一個都沒抓到。

Q3

AI 開的 MR 會不會改壞東西？

AI 只能讀檔和編輯，不能執行指令、碰不到 git 遠端；只准改該 app 的原始碼，改完要過型別檢查和重新巡檢，最後只開 Draft MR，由工程師審核才合併。
